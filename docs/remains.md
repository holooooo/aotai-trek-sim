# 死亡血迹

血迹是游戏死亡记录的地面标记，默认显示本机历史与附近玩家的匿名记录，不渲染实体尸体。靠近到3.2游戏单位内且高度差不超过2单位，可点按钮或按G查看死因和最终状态。查看暂停模拟，不改变物资、体征或方向。

## 偏好与本机保存

标题和菜单都有“死亡血迹”和“匿名共享”两个开关，默认开启，独立于匿名统计。总开关关闭时停止显示、查询和新增记录共享，立即释放可见模型并取消请求；仅关闭共享时保留本机记录显示。关闭任意相关开关会丢弃待发队列，重新开启不补报这些旧记录。已经共享的记录按服务端期限过期，不通过本机清理撤回。

本机键 `aotai-remains-settings-v1` 保存偏好，`aotai-remains-local-v1` 最多保存60条死亡记录及其待发状态。死亡结算在 `ending.remainsId` 中保存稳定随机ID，使重复结算和网络重试幂等。坐标来自实际 `Game.pos.x/z`，不根据路线进度反推。健康按当前难度最大值换算百分比。无网络时本机记录正常显示。

## 附近加载

世界版本为 `aotai-winter-v1`；修改地形后应提升此版本，避免旧血迹落在错误地形。区分主线与四条虚构分支。空间网格边长64游戏单位，每次仅查询当前位置网格及相邻八格；没有获取整张地图数据的接口。客户端最短请求间隔8秒，同一网格缓存60秒，最多缓存8个区域；请求5秒超时。跨区会取消旧请求，关闭或切换行程后旧响应不能重新进入场景。

客户端只实例化56游戏单位内的标记，已有模型超过72单位时释放几何和材质；最多同时显示24个，优先本机记录。场景更新每0.3秒检查一次，而非逐帧请求。返回标题、新开局或读档会清理旧场景，切换后按当前坐标重新查询。

## Pages Functions 与 D1

`GET /api/remains?world=aotai-winter-v1&path=main&cx=0&cz=0` 必须包含全部参数，不接受未知或重复参数。服务端按 `(world,path,cell_x,cell_z,expires_at)` 索引筛选相邻3×3网格，只返回未过期记录，按到查询格中心距离排序，最多24条。

`POST /api/remains` 接收 `id,world,path,x,z,role,difficulty,cause,gameMinute,core,health,food,water,stress,altitude`，严格枚举和范围校验，同源JSON，最多2048字节。坐标为游戏模拟坐标，保留两位小数。无姓名、浏览器编号、IP、现实地理位置或自由文本。接口不证明记录来自未修改的游戏客户端，档案不是权威事故记录。

服务器赋予 `createdAt` 和30天有效期，客户端不能延长记录有效期；重复ID使用 `INSERT OR IGNORE`。GET过滤过期记录，POST时通过过期索引每次最多删除100条过期行。数据库缺失或不可用返回503，游戏保留本机功能。

部署前执行 `wrangler d1 migrations apply DB --remote` 应用新增迁移 `0002_remains.sql`，然后按现有流程部署Pages。单元测试用内存SQLite，浏览器测试mock社区API；HTTP集成测试仅使用隔离的本地D1，不向生产提交验收血迹。

## 预告片

`promo/film.html?shot=bloodtrail` 是7秒独立镜头，显示发现血迹、靠近G键查看、自己的失温记录、匿名记录以及弹幕“又是类魂...”。主合成在42.28秒插入此段，原后续剧情、字幕和声音整体后移7秒，导出67秒竖屏完整预告片。
