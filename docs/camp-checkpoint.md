# 营地余温

成功收起帐篷或结束露宿、起身出发后，会自动更新本局的「营地余温」回溯点。不要求点燃炉火，不消耗额外燃料。

遇难时，如果有有效回溯点，会先给出两个选择：

- **从最近一次收营后继续**：恢复收营完成那一刻的位置、时间、身体状态、物资、NPC、同行者及剧情进度。收营之后的进展撤销，不额外扣除物资；恢复后营地已收起，角色停止自动行走。
- **接受这次遇难**：进入原有的遇难结算，照常记录结局和死亡血迹。

同一处余温可以反复使用，直到下一次成功收营将其替换。在收营过程中遇难，不会覆盖上一处余温。全新游戏不会继承旧局余温。离开营地不改变原有炉火余额规则。

## 存档与结局

回溯点随本局 `aotai-save-v1` 主存档一起保存。死亡选择尚未确认时刷新或关闭页面，重新读取存档仍会回到选择，不会自动回溯，也不会提前记入遇难结局。

继续回溯被视为同一局重试：不写永久死亡结局、血迹和 `run_ended`，保留当前遥测运行标识、累计活跃时间与已发送事件键，避免倒退遥测或重复统计。接受遇难后仍使用原有结局流程。

快照不包含自身与遥测，避免每次扎营都嵌套增长；它与当前状态互不共享可变对象。加载时校验版本、角色/种子/难度归属、路线、位置和关键状态。旧档或损坏的余温会被视为没有回溯点，不会因此拒绝主存档。

存储写入失败时会提示当前页面仍可回溯，但不承诺刷新后仍可恢复。此机制仅用于虚构游戏，现实中生命无法重来。

## 验证

单元测试覆盖收营提交、露宿、坏帐篷、失败收营、深拷贝、重复回溯、待选死亡存档、接受结局、损坏快照降级及旧异步流程取消。

浏览器验收分为实际搭建测试营地后点击收营的开发态流程，以及不使用开发全局变量的生产构建流程，均覆盖手机与桌面端。
